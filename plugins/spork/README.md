# Spork

Fork the current conversation into a new Herdr location, then optionally send
a seed prompt. Both OpenCode and Pi support `/spork` and the quick shortcuts
`/spork tab`, `/spork worktree`, `/spork right`, and `/spork down`.

Both interfaces offer **New tab / Worktree / Right / Below**, defaulting to New
tab. Each host uses its built-in destination selector followed by a seed-input
dialog: Pi's multiline editor or OpenCode's prompt, with the host's standard
controls. Cancel either dialog to stop without creating
resources; submit an empty seed to open an idle fork. The quick shortcuts skip
the dialogs.

OpenCode also asks for an optional Herdr tab or worktree workspace title between
destination and seed; splits skip this prompt. An empty title keeps the automatic
label. This does not rename the OpenCode/Pi session or change the autogenerated
Git branch or worktree path. The seed is prefilled with
`You are now in a forked agent conversation.`; edit it or clear it to leave the
fork idle. Canceling any prompt stops before creating resources. The title is
applied when creating the Herdr destination, before launch.

## Loading

- OpenCode: load `plugins/opencode/spork` in the `plugins` array of
  `~/.config/opencode/cli.json`. This repository's `config/opencode/cli.json`
  already does so. Restart the TUI after changing plugin code.
- Pi 1.1.0: load `~/dotfiles/plugins/pi/spork/index.ts` in the `extensions` array
  in Pi's settings. This repository's `config/pi/settings.json` already does
  so. Restart Pi or use `/reload` in existing conversations.

Both entrypoints import `plugins/spork/core.ts` directly; no build is required.

## Shared workflow and agent adapters

`core.ts` owns Herdr topology, focus, Git base validation, startup ordering,
and recovery messages. An adapter supplies the agent kind, source directory,
fork creation, launch preparation/arguments, and targeted seed delivery.
Rendering and agent-specific preflight checks stay in each entrypoint.

- OpenCode forks through its connected client, moves the fork when necessary,
  and sends the seed through the client to the fork's session ID. It currently
  requires the default local OpenCode service.
- Pi opens a separate `SessionManager` and extracts the current active branch
  through its leaf. This does not switch the source conversation. The new
  session records the target directory and source as its parent; custom session
  storage is respected. Current model/thinking selections are passed to the
  child process. Seeds are sent through Herdr to the new Pi pane after startup.
  Pi's `ctx.fork()` and CLI `--fork` are intentionally not used: the former
  replaces the source runtime, while the latter can resume a different saved
  branch after tree navigation.

Worktree destinations use native `herdr worktree create`, with the default branch
and an automatic `spork/<random-id>` branch. Herdr manages the path and linked
workspace. No fetch/pull or copying of uncommitted edits occurs. The source's
repository-relative subdirectory must exist on the default branch.
When invoked from an existing linked worktree, creation is directed through the
repository's main checkout, as Herdr requires. History still comes from the
current conversation, not a conversation in the main checkout.

Default-branch detection prefers `origin/HEAD`, otherwise a sole remote HEAD.
It uses the matching local branch when available, or the existing remote-tracking
ref when not. Without a recorded remote default, local `main` then `master` are
the conventional fallbacks. It never uses the current feature branch as a fallback.

The source conversation must be idle and nonempty; Pi conversations must also
be saved. Every submission creates a separate fork. Blank seeds leave it idle;
nonblank seeds start a turn after startup succeeds. If creation or launch fails,
resources are retained and identified in the error. Seed errors are reported
without automatically retrying uncertain delivery.
After creating a destination, failures also show a Herdr notification so they
are visible even when the source tab is hidden. Explicit pre-launch
`agent_pane_busy` rejections are retried for up to three seconds while a new
shell initializes. Other launch errors and timeouts are not retried, to avoid
starting duplicate agents.

## Persistent failure log

Shared-workflow failures are appended to
`~/.local/state/spork/failures.jsonl` (or `$XDG_STATE_HOME/spork/failures.jsonl`).
This is one JSON object per line, shared by Pi and OpenCode and independent of
any tab or worktree, created on the first failure. It records the timestamp, stage, source/destination paths
and pane/workspace IDs, source/fork references, launch rejections/retries, error
code/message/stdout/stderr/stack, and a best-effort destination process snapshot.
Seed text is redacted from error strings; environment variables are not dumped.
The file is created with owner-only permissions. No automatic deletion or
rotation is performed.

The failure toast and Herdr notification point to this file. Failure to write
the log is reported explicitly without hiding the original error. Herdr's own
event and plugin-command histories are bounded in-memory buffers, not durable
logs of these calls.

Read the latest failures from any checkout:

```sh
tail -n 5 ~/.local/state/spork/failures.jsonl
```
